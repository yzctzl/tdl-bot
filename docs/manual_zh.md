# 使用手册

[English](manual.md) · [首页](../README_zh.md) · [安装指南](deployment_zh.md)

这份手册写给准备部署、使用并管理自己 Bot 的你
默认你是 Bot 的所有者和管理员，可以一个人使用，也可以邀请自己的其他账号或可信协作者
不需要先学习 Bot 命令或项目实现，日常操作以按钮为主

还没安装？请先按[安装指南](deployment_zh.md)完成配置，再从下面的“第一次使用”开始

## 先分清三个位置

配置成功后，你主要在 Telegram 中操作，终端只在启动、停止、升级和增加登录时使用
先记住三个位置，后面的设置就更容易理解：

| 名称 | 是什么 | 你需要做什么 |
| --- | --- | --- |
| Bot 对话 | 你与自己创建的 Bot 的私聊 | 在这里发送链接、点按钮和查看任务进度 |
| 内部存储 | 部署时选择的频道或群组，用于保存内容及必要操作记录 | 保持 Bot 和所有执行账号都能访问，不要随意清空 |
| 接收位置 | 你最后查看收藏内容的地方，默认就是 Bot 对话 | 可以改成自己的频道、群组或论坛话题 |

内部存储和接收位置是两个独立设置
第一次使用时，先保留“接收到 Bot 对话”，确认能成功保存一条内容，再设置收藏频道
这样遇到问题时更容易确认是哪一处权限没有配好

## 第一次使用

### 1. 打开自己的 Bot

安装向导验证 token 时会显示 Bot 的 `@用户名`
在 Telegram 中搜索它，打开私聊，点击开始或发送 `/start`
第一次会出现中英双语提示，点击 **简体中文** 或 **English**，之后可以在设置中随时修改
语言只影响界面，来源文字不会被翻译

### 2. 确认你有管理员入口

主界面显示你的账号、接收位置、活动任务、待重试数量及追踪概况
你应该能看到三行主要按钮：

| 第一列 | 第二列 |
| --- | --- |
| 任务管理 | 定时追踪 |
| 用户管理 | Bot 管理 |
| 设置 | 帮助 |

如果没有第二行，当前 Telegram 账号没有管理员权限
首次部署时，请确认你打开 Bot 使用的账号，就是向导第三步确认的管理员账号
已有数据库的安装，不会通过修改 `.env` 中的 `ADMIN_USER_IDS` 重置角色，需要使用已有管理员账号进入“用户管理”调整

### 3. 检查内部存储

点击 **Bot 管理**，直接查看内部存储是否为你部署时准备的频道或群组
向导已经完成存储配置时，不需要再设置一次
Docker 手动部署尚未配置时，点击 **修改存储**，输入存储的 `@用户名` 或 ID

Bot 需要能读取并复制其中的消息，执行账号需要能写入
频道中请将 Bot 设为有发帖权限的管理员，并关闭频道的内容保护/限制保存选项
配置与登录问题见[安装指南](deployment_zh.md#开始前准备)

### 4. 保存第一条内容

先选择一条自己登录账号能直接打开的小视频或图片消息，复制消息链接，发送到 Bot 私聊
等待进度到 `5/5`，确认媒体和文字出现在 Bot 对话中

看到完整内容，就说明来源访问、内部存储和最终发送已经跑通
之后再尝试媒体组、私有来源或自定义接收位置，便于逐项确认设置

## 保存消息与媒体组

### 发送什么链接

打开 Telegram 中想保存的消息，从消息菜单复制链接，粘贴到 Bot 私聊发送即可
请复制**具体消息的链接**，而不是频道主页或加群邀请链接

例如 `https://t.me/example_channel/123` 指向一条消息；`https://t.me/example_channel` 只是频道主页
这里的地址只是格式示例，请换成你实际要保存的消息链接

如果消息属于一个媒体组，发送其中任何一条的链接即可，不需要把每张图片的链接都发一遍
Bot 会查找同组其他成员，一起处理图片、视频和文字，保留顺序及文字格式
已保存内容会移除媒体隐藏效果和原发送者的转发署名

支持公开消息、私密 `/c/` 消息、论坛消息、`/s/` 预览及支持的讨论评论链接
私密链接不等于访问权限，执行账号仍需能读取来源

### 怎么看进度

Bot 引用你发来的链接，回复一条进度消息，并在原消息内更新，不会每一步都额外发一条：

| 步骤 | 表示什么 | 你需要做什么 |
| --- | --- | --- |
| 1/5 加入队列 | 任务已接收，等待处理 | 等待，不需要重复发送链接 |
| 2/5 定位媒体组 | 查找消息和同组其他内容 | 无需操作 |
| 3/5 准备媒体 | 正在准备，需要传输时显示下载、上传或下载并上传 | 大文件可能停留较久，保持服务运行 |
| 4/5 发送媒体 | 正在发送到接收位置 | 等待发送结果 |
| 5/5 完成 | 媒体及文字已发送 | 到接收位置查看 |

准备耗时会随文件大小、网络和 Telegram 的限制变化，不是每一步用时都一样
保存过且仍可访问的内容，再次发送时通常更快，无需手动选择处理方式

### 想中途停止

点击进度消息下方的 **取消**，等待消息显示已取消
取消会清理本次任务的本地临时文件，已经发到 Telegram 的内容可能保留，不会自动撤回
任务结束后取消按钮会移除

浏览菜单不会覆盖任务进度，可以一边等任务，一边处理其他设置

## 设置接收位置

### 接收到 Bot 对话

这是默认设置，适合先试用，也不需要额外添加 Bot 到其他频道
需要恢复默认时，点击 **设置 → 接收设置 → 接收到此对话**
也可以直接发送：

```text
/target bot
```

### 接收到频道或群组

1. 在 Telegram 中准备一个已有频道或群组，例如你的收藏频道
2. 将 Bot 添加进去，频道需授予管理员发帖权限，群组需允许发送文字及相关媒体
3. 确保你自己的操作账号也能访问这个目标
4. 回到 Bot 私聊，点击 **设置 → 接收设置 → 设置群组或频道**
5. 按提示发送目标的 `@用户名` 或数字 ID，私有频道通常需要数字 ID
6. 检查返回页面中的接收位置，再发送一条新消息链接验证

在按钮要求输入目标时，只需发送目标本身，不必附带 `/target`
想用命令设置时，完整格式为：

```text
/target @my_collection
```

Bot 不会自动创建频道，也不能主动向未与它建立对话的其他私人账号发送内容
这里的个人接收位置，是你自己的 Bot 对话

### 接收到论坛话题

先按群组目标准备好 Bot 权限，再在目标后面加话题 ID，中间用空格分隔：

```text
/target @my_forum 42
```

话题 ID 是该分区的数字编号，不是话题名称
例如链接结构为 `t.me/c/<群编号>/42/<消息编号>` 时，`42` 是话题 ID，最后一段是消息 ID；带 `?thread=42` 的链接也明确指定话题 42
如果拿不准，先不指定话题，确认群组可以收到内容后再设置
状态中会显示可点击的目标/话题链接，可用来确认位置

修改接收位置只影响**新任务**
已接收任务及待重试记录仍使用原来的位置，不能靠修改设置重定向旧任务

## 定时追踪与历史搬运

### 先选择你需要哪一种

| 需求 | 使用功能 | 入口 |
| --- | --- | --- |
| 从现在起定期收集新发布的内容 | 定时追踪，命令名 `follow` | 主界面 → 定时追踪 |
| 把来源中已有的历史内容搬过来 | 历史搬运，命令名 `dump` | Bot 管理 → 历史搬运 |

两种功能都支持媒体组、单个媒体和纯文字，忽略服务通知
都不会自动创建目标频道，也不会同步来源后续的编辑与删除

### 创建定时追踪

1. 点击 **定时追踪 → 新增追踪**
2. 按提示发送来源的 `@用户名`、ID 或链接，私有来源需要执行账号有访问权限
3. 在确认页面检查来源，点击 **接收位置** 选择目标
4. 想发到单独的备份频道，选择 **设置群组或频道** 并输入目标；想只保存在内部存储，保留 **默认**
5. 点击 **间隔**，选择预设值，或输入 `5m`、`1h` 之类的自定义值
6. 确认来源、接收位置与间隔无误，再点击 **开始追踪**

默认每五分钟检查一次，最短 60 秒
创建后会显示任务详情，包括状态、已处理数量、间隔，以及适用时的下次检查时间
来源暂时没有新消息时，计数不增加是正常现象

追踪只处理**创建时最新消息之后**发布的内容，不会补齐更早的历史
这里的“默认”指**仅保存到内部存储**，不是你在设置中选择的个人接收位置
如果想在收藏频道收到追踪结果，创建时一定要明确选择它

命令等价写法：

```text
/follow @source_channel to @backup_channel every 5m
```

### 创建历史搬运

1. 点击 **Bot 管理 → 历史搬运 → 新增搬运**
2. 发送要搬运的来源频道或群组
3. 在确认页面选择接收位置，省略时仅保存到内部存储
4. 确认后点击 **开始搬运**
5. 在任务详情查看进度，内容按从旧到新的顺序搬运，媒体组整体处理

任务只搬运执行账号可见的历史，并在创建时固定结束位置，新消息不会让任务一直延长
需要长期收集后续内容，再创建定时追踪

命令等价写法：

```text
/dump @source_channel to @backup_channel
```

重新创建相同历史的搬运任务，可能再次发送已经搬过的内容
历史搬运和追踪是两个独立任务，同时使用时，先创建追踪可以避免两次创建之间的空档，但交叠内容可能重复发送

### 暂停、修改、取消和恢复

打开对应功能的任务列表，点击具体任务，再选择操作：

| 操作 | 结果 |
| --- | --- |
| 暂停 | 保留进度，之后可以恢复 |
| 恢复 | 按已保存进度继续，不会重新创建一个从头开始的任务 |
| 修改间隔 | 改变追踪检查频率，不改变原来源与目标 |
| 取消 | 结束任务，不能恢复，已发送内容保留 |

已取消任务在列表中显示七天，之后从列表隐藏
新目标或执行账号设置不会改变已有任务，需要使用不同目标时请新建任务
大批量搬运会自动控制节奏，遇到 Telegram 限流会等待其要求的时间，不需要反复暂停/恢复来催促

如果任务提示“上次发送结果未确认”，请先检查目标中是否已有这组内容：

- 已确认完整收到：选择 **跳过当前项**，避免重复发送
- 已确认没有收到：选择 **重试当前项**
- 只收到一部分或无法确认：先核实内容，不要连续重试，重试可能留下重复副本

## 任务与失败处理

### 查看和取消活动任务

点击 **任务管理**，页面直接显示当前状态
进入 **活动任务**，选择任务后可以查看来源、接收位置、当前阶段及取消按钮
任务结束后从活动列表消失，最终结果仍在原进度消息中
需要最新计数时，使用动态列表上的刷新按钮；返回其他页面会自动读取新状态

### 来源需要加群时怎么办

如果链接处理因来源访问权限不足而进入待重试：

1. 打开 **任务管理 → 重试管理**
2. 点击对应记录，确认来源和目标
3. 如果已处理好权限，点击 **重试**
4. 还没有加入来源时，点击 **加群并重试**，发送来源主页或邀请链接
5. 确认界面显示的执行账号，再确认加群

成功加入后会重试，若提示等待审批，请先等待来源管理员批准，再回到同一记录点击重试
不需要先提交失败任务也可以加群，入口为 **任务管理 → 加群**
加群动作使用执行账号，不是让 Bot 加入来源

加群无法恢复已删除内容、绕过封禁或显示来源未开放的历史
如果你在一个账号里看得见来源，但 Bot 仍提示不可访问，请先检查 Bot 实际使用的是哪个执行账号

### 不想再重试

在记录详情点击 **删除记录** 并确认
这只移除记录，不撤回已发媒体，也不会自动退出已经加入的群
如果记录正在重试，先取消活动任务，再移除记录

管理员不受三条待重试记录的限制
普通成员最多保留三条，满额后必须先重试或移除，才能继续提交新链接
这项限制不会影响你以管理员身份使用自己的 Bot

## 管理执行账号

### 一个账号就够开始

不需要为日常使用配置多个账号
向导登录的 Telegram 账号就是公共执行账号，它负责读取来源和准备内容
你可以用这个账号操作 Bot，也可以从已授权的其他 Telegram 账号操作同一个 Bot

没有登录个人会话的成员，使用公共执行账号
因此来源是否可见，取决于**执行账号能否访问**，不只取决于发链接的账号

### 增加自己的其他账号

原生安装时，在工作目录终端依次执行：

```sh
tdl-bot stop
tdl-bot login -n personal
tdl-bot run
```

`personal` 是给这份登录起的名字，可以改成自己容易识别的名称
登录时扫描对应账号的二维码，不要再次登录成原账号
Docker 的对应步骤见[安装指南](deployment_zh.md#复用或增加登录)
每个执行账号都要能写入内部存储

重新启动后，已登录的个人账号与操作 Bot 的账号 UID 相同，就自动使用自己的会话，否则仍使用公共执行账号
登录不会自动授予 Bot 使用权限，其他操作账号还需要在用户管理中添加

### 管理员切换使用账号

打开 **Bot 管理 → 执行账号**，查看已加载账号及当前选择
选择某个账号，可以让你之后提交的新任务使用它
选择 **自动** 恢复“有自己的就用自己的，否则用公共账号”的规则

选择只影响你自己的新任务，不会改掉其他成员的账号，也不会改变已有任务或重试记录的执行身份
普通成员没有这个切换入口，不能借用别人的个人账号

## 管理成员与使用记录

### 只有自己使用，可以跳过成员配置

首次部署确认的管理员已可使用全部管理功能，不需要再添加自己一次
只有准备让其他账号或协作者操作 Bot 时，才需要添加成员
工作空间面向可信协作，不提供成员之间相互隔离的私人收藏环境

### 添加一个账号

1. 点击 **用户管理**，进入成员列表
2. 点击添加入口，输入对方的 `@用户名` 或 UID
3. 确认操作后，让对方打开同一个 Bot 的私聊并发送 `/start`
4. 对方选择语言后，即可发送链接，并设置自己的接收位置

没有用户名或暂时无法解析时，让对方先使用 `/whoami` 获取 UID，再用 UID 添加
成员权限绑定 UID，之后修改用户名不会转移权限

### 查看和调整成员

成员列表用按钮翻页，点击账号直接进入详情
这里可以查看角色、封禁状态、接收位置和追踪使用量，再做相应修改：

| 操作 | 什么时候使用 |
| --- | --- |
| 修改接收位置 | 帮其他账号修正发送目标 |
| 设置角色 | 需要协助管理 Bot 时设为管理员，不需要管理权限时保留普通成员 |
| 封禁 / 解封 | 临时暂停使用，可选一天、一周或 30 天，也可以提前解封 |
| 删除 | 撤销该账号的 Bot 使用权限 |
| 追踪配额 | 调整普通成员可保留的追踪任务数，范围 0–1000 |

普通成员默认最多九条追踪，活动和暂停任务都计数，取消后释放名额
降低配额会保留已有任务，但新建及恢复时需符合新配额
管理员不设追踪数量上限

封禁或删除会停止该成员的活动任务，已完成的内容不撤回，也不删除服务器上的登录会话
最后一个有效管理员不能被删除、封禁或降级，避免把自己锁在管理入口外

### 查看谁处理了什么内容

在用户管理中打开历史入口，查看所有人的链接及加群记录，也可以按成员查看
管理记录通过标签切换，和内容处理记录分开显示

链接及显式加群操作也会在内部存储中留下简洁记录，其他日常按钮和命令不会全部刷进去
记录优先显示用户名；失败或取消的链接带删除线
再次保存已有内容时，记录关联已有媒体，不额外复制一份媒体到内部存储

## 日常设置与维护

### 修改语言

点击 **设置 → 语言设置**，选择英文或简体中文
每个操作账号独立保存，重启后保留，来源文字不变

### 修改内部存储

先准备新频道或群组，授予 Bot 和所有执行账号权限
再点击 **Bot 管理 → 修改存储**，按提示发送新位置
修改后检查显示的位置，并用新链接验证

此操作不会自动迁移旧媒体，已经接收的任务仍保留原存储位置
旧频道中已有结果可能仍被使用，不要在修改设置后立刻删除旧频道
接收位置的修改请使用“设置 → 接收设置”，它与内部存储互相独立

### 更新 tdl 和更新 Bot

**Bot 管理 → 更新 tdl** 用于更新负责传输的 tdl 程序
选择最新版本后，会先比较版本，需要时才下载更新，活动任务结束后再替换，失败保留原程序
这不会更新 tdl-bot 本身

更新 Bot、备份数据、停止和重新启动，请按[安装指南](deployment_zh.md#停止重载与升级)操作
不要直接删除安装目录或登录目录来尝试修复任务错误

### 需要命令时

点击 **帮助** 会显示你当前角色可用的完整命令
按钮已经覆盖日常操作，命令主要用于直接输入或熟悉后的快捷操作
例如 `/status` 查看状态，`/user h` 查看历史；子命令可以使用不歧义前缀，有歧义时不会执行

## 常见问题

### Bot 能回复，但内容发不出来

先保留接收到 Bot 对话，确认来源在执行账号中可访问
再检查 **Bot 管理**显示的内部存储，以及 Bot 是否已加入该位置、有发帖权限，且没有内容保护
如果 Bot 对话能收到、收藏频道收不到，再检查收藏频道的 Bot 权限及话题 ID
不要只检查最终目标，内部存储权限同样必需

### 提示可能已有部分媒体上传

先检查接收位置，确认是否已收到全部或部分内容
网络中断有时发生在发送完成之后，立即重复提交可能产生重复内容
普通链接任务确认后再决定是否重新发送；历史搬运或追踪使用任务详情中的重试/跳过操作

### 自己能查看来源，Bot 却提示需要加群

检查 **Bot 管理 → 执行账号**，确认实际使用的身份
如果使用的是公共账号，需要它加入来源，而不是仅让你发链接的账号加入
涉及审批时还要等待批准，加入后也未必能看到来源限制的旧历史

### 创建追踪后没有立即收到内容

追踪不搬运创建之前的历史，先检查任务是否显示运行中，以及下次检查时间
想测试时，在有权限的测试来源创建追踪后发布一条新消息，等待至少一个轮询间隔
需要旧内容请使用历史搬运

### 旧按钮无效，或设置完目标后旧任务仍发往原位置

旧按钮失效时重新发送 `/start`
目标及账号修改只作用于新任务，旧任务与重试保留原设置，需要新位置时提交新任务

启动、Docker 目录、代理和 Windows 的问题，见[安装排错](deployment_zh.md#常见问题)
