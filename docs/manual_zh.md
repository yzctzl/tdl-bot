# 用户手册

[English](manual.md) · [首页](../README_zh.md) · [安装指南](deployment_zh.md)

## 第一次使用

管理员完成部署并为你授权后，打开 Bot 的**私聊**，发送 `/start`，选择英文或简体中文
语言选择会保存，不会改变媒体原文的语言

主界面显示账号、接收位置和任务概况，按钮按以下功能划分：

| 入口 | 可以做什么 |
| --- | --- |
| 任务管理 | 直接查看当前状态，管理活动任务、待重试记录，以及加入来源群组 |
| 定时追踪 | 创建追踪，查看进度，暂停、恢复、修改间隔或取消 |
| 设置 | 选择接收位置和界面语言 |
| 帮助 | 显示当前角色可用的命令 |
| 用户管理 — 管理员 | 管理成员、权限、配额和历史记录 |
| Bot 管理 — 管理员 | 搬运历史、配置内部存储、选择执行账号和更新 tdl |

进入或返回页面时，会读取最新概况
任务进度使用独立消息，浏览菜单不会覆盖进度
旧按钮失效时，重新发送 `/start` 即可
按钮与命令都可以使用，输入命令会退出菜单当前等待文字输入的步骤

## 保存消息与媒体组

在 Bot 对话中发送 Telegram **消息链接**
链接指向媒体组中的任意一条消息，都能选中整个媒体组，包括其他成员上附带的文字
图片、视频及文字保留来源顺序与文字格式，已保存内容会移除预览遮罩

支持公开消息链接、私密 `/c/` 链接、论坛消息链接、`/s/` 预览链接及支持的讨论评论链接
私密链接本身不代表访问权限，执行搬运的账号必须能读取来源

Bot 会引用链接回复**一条进度消息**，在原消息内依次更新：

| 步骤 | 含义 |
| --- | --- |
| 1/5 加入队列 | 任务已接收 |
| 2/5 定位媒体组 | 查找消息及同组的其他媒体 |
| 3/5 准备媒体 | 准备内容，需要传输文件时显示下载、上传或下载并上传 |
| 4/5 发送媒体 | 将准备好的内容发送到你的接收位置 |
| 5/5 完成 | 媒体及文字已发送 |

点击消息下方的**取消**，或在任务管理中选择任务取消
取消会等待本地清理，已经发到 Telegram 的内容可能保留，取消不等于撤回
任务结束后会移除取消按钮

保存过的内容可以无需再次下载就发送，同一媒体组中能被识别的其他链接也适用
前提是已保存的副本仍然可访问，这不代表能无限期找回已删除内容

## 选择接收位置

打开**设置 → 接收设置**，默认接收到 Bot 对话
也可以输入频道或群组的 `@用户名` 或 ID，需要话题时在后面加话题 ID：

```text
/target bot
/target @my_collection
/target @my_forum 42
```

请先准备已有目标，Bot 不会自动创建频道
将 Bot 加入目标，并授予发送相关消息和媒体的权限
频道需要将 Bot 设为有发帖权限的管理员，私有目标可能需要使用数字 ID
状态中的位置或话题链接，会在 Telegram 支持的情况下打开对应位置

修改只影响**新任务**，已接收任务和待重试记录保留创建时的目标与执行账号
修改接收位置不会改变待重试任务的去向，可用 `/status` 确认当前设置

## 任务、重试与加群

任务管理页面直接显示当前状态
活动任务中可以查看进度和取消，待重试记录中可以重试、移除或按需加群后重试
普通成员管理自己的个人任务，管理员可以管理所有任务，但仍需满足执行账号的使用权限

来源要求加入时，选择**加群**并发送群主页或邀请链接
不依附失败任务，也可以独立加群
关联待重试记录的加群，会使用原任务的执行账号
需要审批的来源，要先等待来源管理员批准，再重试

```text
/pending
/retry <id>
/join https://t.me/+INVITE <retry_id>
/retry_cancel <id>
```

普通成员最多保留**三条待重试记录**，满额后需先重试或移除，再提交新链接
等待加群审批仍使用原记录，不额外占用名额
移除仅删除重试记录，不执行加群或传输；正在重试的任务需先取消，再移除记录
管理员不受此数量限制

加群无法恢复已删除的消息、绕过封禁，或显示来源不向你开放的历史
原执行账号不可用时，请管理员恢复，不会悄悄改用其他身份重试

## 定时追踪与历史搬运

### 追踪新消息

在**定时追踪**中选择来源、可选的接收位置及间隔
追踪从**创建时来源中最新消息之后**开始，默认每五分钟检查一次，最短间隔为 60 秒
复制新发布的媒体组、单个媒体与纯文字，忽略服务通知，不同步编辑与删除

```text
/follow @source_channel to @backup_channel every 5m
/follow @source_channel every 10m
/follow interval <id> 1h
```

目标准备与 Bot 权限要求和普通发送相同
省略目标时，仅保存到服务的默认存储，**不会**发送到你的个人接收位置，也不会自动创建频道

普通成员默认最多 **9 条追踪**，活动和暂停的追踪都计入数量，取消后释放名额
管理员可以调整个人配额
降低配额不会移除已有追踪，但新建和恢复时必须符合新配额，管理员不设数量上限

### 搬运历史 — 管理员

在 **Bot 管理 → 历史搬运**中选择来源和可选目标
历史搬运按从旧到新的顺序复制可见历史，将媒体组作为整体处理
创建时就固定最后一条消息，新消息不会让搬运无限延长，后续消息请使用追踪

```text
/dump @source_channel to @backup_channel
```

执行账号必须能访问来源，只能搬运该账号可见的历史
省略目标时仅保存到内部存储，重新创建相同历史的搬运任务可能再次发送这些内容
历史搬运与追踪是独立任务，不提供原子的交接
两者配合使用时，先创建追踪可以避免两次创建之间的空档，但重叠的消息可能重复发送

### 暂停、恢复与异常处理

两类任务都支持查看状态、暂停、恢复和取消
暂停保留进度，取消不可恢复，已取消任务在列表中保留七天
任务始终保留原执行账号和目标

Telegram 限流及可安全重试的网络失败会延后重试
发送结果不确定时，任务暂停，不会猜测是否已经发送成功
请先检查目标，再选择界面提供的重试或跳过
重试可能重复发送已成功但未收到回执的内容，跳过则可能遗漏实际未送达的内容

大批量备份会自动控制发送节奏
暂时没有进度，可能是在等待 Telegram 要求的延迟，或下一次追踪检查时间

## 多账号与协作

这是供可信成员共用的工作空间，不是相互隔离的公开托管服务
如果成员之间的收藏必须隔离，请不要放在同一个工作空间
每位成员拥有自己的接收位置和语言设置，管理员管理权限、任务和历史
提交的媒体链接及主动加群操作会记录下来供管理员查看，内部存储也会留下简洁记录
其他日常命令不会作为活动记录发送到那里

向 Bot 发指令的账号，与读取来源的账号不一定相同
服务器上已登录自己的 Telegram 账号时，会自动使用自己的账号，否则使用公共执行账号
普通成员无法选择其他人的会话
服务器登录由管理员安排，Bot 对话不会收集登录验证码

## 管理员操作

在**用户管理**中通过按钮翻页，选择成员后直接查看接收位置、角色、封禁状态及追踪使用量，并进行修改
多数成员命令支持 UID 或 `@用户名`，无法解析的用户名仍可能需要 UID
权限绑定 UID，修改用户名不会转移权限

| 操作 | 对应命令 |
| --- | --- |
| 添加 / 删除 | `/user add @person` · `/user remove @person` |
| 封禁 / 解封 | `/user ban @person 1d` · `/user unban @person` |
| 设置角色 | `/user role @person user` 或 `admin` |
| 追踪配额 | `/user follow @person 9` — 范围 0–1000 |
| 历史 | `/user history [@person]` — 活动记录，可切换管理记录标签 |
| 成员接收位置 | `/target for @person @destination` |

封禁期限支持 `1d`、`1w` 和 `1m`，其中 `1m` 固定为 30 天
删除或封禁会停止该成员的活动任务，已完成内容仍然保留
删除成员不会删除服务器上的 Telegram 会话
最后一个有效管理员不能被删除、封禁或降级

**Bot 管理**直接显示 tdl 版本、内部存储和执行账号
Bot 必须能读取内部存储，所有执行账号都必须能向其中写入，删除其中的媒体可能影响后续使用
管理员可以选择任意已加载的执行账号，选择只影响该管理员自己的新任务
更新 tdl 前先检查已安装版本，安装失败时保留原程序

## 命令简写

帮助中提供当前角色完整的命令列表
`/start` 打开菜单，`/whoami` 显示自己的 UID
子命令支持不歧义的前缀，例如 `/user h` 表示历史
有歧义时不会执行操作，会要求输入更长前缀，例如 `/user r` 可能表示 `remove` 或 `role`
用户名和 URL 等参数不能用这种方式缩写

## 常见问题

| 现象 | 检查方式 |
| --- | --- |
| 未授权 | 请管理员添加或解封你的 Bot 操作账号 |
| 来源不可用 / 进入待重试 | 检查执行账号是否加入来源、通过审批，以及能否查看历史 |
| 发送失败 | 确认 Bot 已加入目标及**内部存储**，检查发帖、媒体权限及话题 ID |
| 提示部分媒体可能已上传 | 重新发送前先检查目标，回执中断时内容可能已经发出 |
| 队列已满 | 等待任务完成，重复提交同一链接不会加快处理 |
| 已有三条待重试 | 先重试或移除一条，再发送新链接 |
| 追踪没有旧内容 | 追踪只处理新消息，历史内容请管理员使用历史搬运 |
| 旧按钮无法使用 | 重新发送 `/start` |
| 修改目标后重试仍发往旧位置 | 重试保留原目标，要使用新位置请新建任务 |

启动、代理、Windows、Docker 与更新问题，见[安装与维护指南](deployment_zh.md#常见问题)
